最近我再做一个实验项目，Cathier。主要目的就是练习自己 Claude Code 的手感。

![](/cn/2026/05/3074-76eb7c85.webp)

https://apps.apple.com/us/app/cathier/id6760601647

其中有两个功能，对于我思考未来的世界挺有帮助的。

一个是 **用户反馈自闭环**。我在关于页面里面放了个用户反馈。用户对它有什么需求直接在里面写，后面自动发 Github 的 issue，云端的 Claude Code 自动接任务，写代码，跑测试，再把代码合并到主分支里面，触发另外的流程编译上传到 TestFlight。一般来说，提出需求后的五到十分钟，我可以在手机上使用包含这个功能的新 App。如果我不喊停的话，每过一阵子它会自动的提交到 App Store 审核，然后坐等发布。

另外一个叫 **没事找事儿。**我用 Claude Code 的routines 每四个小时自己想一个足够具体的小功能，然后自己实现，并且发布。我现在基本上就每四个小时 TestFlight 会有一个新的版本提醒我安装，我会和其他用户一起带着好奇的心看这小东西又做出来了什么。

这些小实验后面都为了更真切的触碰一个问题，就是代码这一层在未来工作流中间的位置，到底在哪里。我昨天说[为什么还有人写代码？](http://mp.weixin.qq.com/s?__biz=MjM5NzI0Mjg0MA==&mid=2652377714&idx=1&sn=85eecfb3a2895f53df5225faf994dec5&chksm=bd3040c58a47c9d350eedfd3c5371c76dc7b5ecd032308cf8cbc91609ae5699b33d3901353c6&scene=21#wechat_redirect)‌，其实也在问同一个问题。这绝不是如何**更快**的写代码的问题，而是人类会不会整体从这一层消失的问题。汽车引擎出现了轿夫就从这一层退出了，从而进入了另外一层，驾驶层（现在流行叫驾驭了 Harness），直到这个问题被自动驾驶解决，人类继续离场。

我从来都对科技发展极度乐观，认为它带来的效率提升将无限造福人类，但这种造福有的时候就是以一个层级的工作彻底消失为体现的。我们心安理得的从重体力劳动中解脱出来，或许也要从代码这种重脑力劳动中解脱出来。

当新技术出现时我们最大的误区是以为它是来提高这一层的人类的工作效率的。否也。它是来让人类不要工作的。
